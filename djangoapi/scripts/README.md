# scripts/

These scripts were the original database initialization path, run in order
by `./initdb.sh`. They are **no longer run automatically** — `initdb.sh` now
only applies Django migrations against a database that the `postgis`
container has already restored from `postgis/fela_seed.dump` (see
`postgis/init-db.sh`).

They are kept here, unmodified, for historical reference: they document
exactly how the original FELA dataset (countries, cities, agencies, events,
presentations, speakers, and their relations) was derived and loaded.

## What replaced them

- `djangoapi/FELA/fixtures/historical_seed_data.json` — a Django fixture
  generated by running `001_create_schemas.py` through
  `008_init_relations.py` once against a clean database and then running
  `manage.py dumpdata`. It is the loaddata-ready equivalent of these scripts.
- `postgis/fela_seed.dump` — a `pg_dump` (custom format) of the `events`
  schema plus the Django/auth tables, restored automatically by the
  `postgis` container on first start (see `postgis/init-db.sh`). This is
  the artifact that should be regenerated from the live, accumulated
  database (not just from these scripts) whenever real data has been added
  or edited directly in Postgres, so that future deployments don't lose it.

## When you'd still use these scripts directly

Only if you need to rebuild `historical_seed_data.json` from scratch (e.g.
after a deliberate schema change) — see `djangoapi/initdb_from_empty.sh`
for the bootstrap path that uses the fixture instead of these scripts.

`003_backfill_created_by.py` is still actively used by
`initdb_from_empty.sh` to assign ownership of the loaded fixture data to the
freshly created superuser.

`001_create_extension_postgis.py` is unused/broken (imports a module that no
longer exists in `core`) and was already dead before this change — it was
only ever wired up from the separate `reset-db.sh` dev helper, and even
there its `run()` function was never called.
